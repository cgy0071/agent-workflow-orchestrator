# Windows 原生框架交付设计

适用于原设计的两个核心和九种扩展示例。每项以同一候选版本上的用户操作验收。已有专项验证可以作为回归输入。宿主预览覆盖任务授权读取、撤权、停用和签认复核日期。

| 工作包 | 接口、写入范围与故障处理 | 验收场景 |
|---|---|---|
| 插件生命周期、升级和回退 | Core 持有插件版本、能力目录与每项目启用状态。安装先校验清单、摘要、API、依赖和权限，再加载。升级先验证新版本，原子切换新任务，既有 Run 保留原版本。 | 同一宿主启用两个项目，停用 A 后旧句柄失效，B 正常运行。破坏升级包后仍可运行旧版。 |
| Registry、技能与 Runtime | Registry 持有获批角色和能力需求，Skill Engine 持有版本化技能，Runtime 持有轮次、工具调用和检查点。任务和委派交给 Scheduler。工具有独立调用授权。 | 从新包添加角色和技能，旧 Run 恢复原版本。工具结果丢失时按幂等键恢复，子任务审核后父任务仅恢复一次。 |
| 模型与 Harness | 按能力、预算和许可目的地挑选 Provider，按适配器实测声明选择会话操作。提交前可切换供应商，已产生输出后保存部分结果并交回复核。 | 同一 Profile 切换模型；增加 Harness 时 Planner 无需改动。不支持的取消或恢复返回可识别错误。真实验收分别记录 Claude、Codex 版本，Grok Build 单列。 |
| Workflow、调度、观察 | Workflow 将版本化模板编译为计划，Scheduler 持有任务、依赖与派发权。观测端按项目订阅带序号的事件，断线从游标重放。审核和预算仍由原服务持有。 | 新模板通过分支、并发、人工干预与冷重启，JOIN 只解锁一次；重放遥测不会触发第二次派发。 |
| 项目知识、来源和记忆 | 资源以项目、稳定 ID、修订和来源摘要定位。区分保留副本和仅登记的外部来源。索引可重建；组包时检查读权限，写回时再次独立检查写权限。判断与引文携带持有人、关系、来源位置。 | 原材料撤除后可核对获准保留的引文；仅登记的材料显示不可用。换检索后端保持相同接口。跨项目读、引用披露和写回独立验收。 |
| 科研领域及连接器 | 领域包声明技能、资源类型、解析器和工具权限。外部连接器通过相同读取协议报告当前修订、分页、取消与来源。 | 用两套合成领域数据替换领域包；停用代表性连接器后本地已保留知识仍可查，源端写操作需单独授权。 |
| 集成与 Windows 分发 | 集成负责人锁定具体分发包。执行、知识和观测工作包可并行；冻结接口后组合，文档、演示和发布档使用同一版本。 | 从 GitHub 首页开始，第二台 Windows 独立安装、按授权执行、获得带出处的结果、撤权、重开及卸载。稳定版应具备这一候选的验收记录。 |

共享接口变更由 Chief 先审。以上是交付验收条件。离线实现、真实服务验证和公开版可用性分别记录。LangGraph 继续暂停。可选适配器按使用场景逐项登记，避免把可选后端列为宿主安装前提。
