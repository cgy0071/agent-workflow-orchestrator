# 原生框架：功能与验收边界（2026-11-19）

首版架构设计已交付：13 份指定文档、Model Gateway 和 Observability 两份补充设计、9 份编号 ADR（另有索引）。本次核对了设计清单中的 29 个 SHA-256。下表区分已有的 Windows 离线证据和仍缺的验收，不将不同提交的结果拼成一次发布验收。

| 模块 | 已观察到的结果 | 仍待证明 |
|---|---|---|
| Core / 插件 | 单进程按项目停用模型插件；独立项目可继续使用 | 不受信任的插件进程隔离 |
| Model Gateway | 本地安装并激活可信 provider；不改 Runtime 或 Profile 即可调用 | 真实供应商的互操作、路由和费用结算 |
| Agent Runtime | 挂起的父会话恢复并只读取本次委派的已审核结果；不重发未知结果 | 多宿主并发恢复 |
| Registry / Skill | 经批准登记角色；切换技能后，恢复的旧会话使用原版本，新会话用新版本 | 生产身份发放；任意执行阶段的升级恢复 |
| Workflow | 固定容量场景可恢复等待任务，不重复提交；Scheduler 保有调度权 | 动态容量策略、真实唤醒服务 |
| Harness | Grok Build 模拟 CLI 的 Windows 超时清理和拒绝路径通过 | 真实 Grok Build 会话 |
| Observability | 按项目查询、有界事件及脱敏导出 | 生产部署的遥测验收 |
| Project Context Hub | 更换检索后端仍返回有效引用；两个合成项目可授权披露选定内容；撤权后拒绝旧引用 | 真实数据源接入；干净 Windows 主机首次使用 |

最近一次独立验证针对 SHA-256 为 9a0caf4e84a9c332c87af18e7caedcc5f308d0a7126cdfec7264088543476656 的 CLI 包。工程测试覆盖并发撤销的先后顺序；独立验证覆盖顺序撤销、凭据隔离、旧协议拒绝及实际返回字节。协作式单机测试不能推断已交付字节可被收回。

下一步：先把必要模块、版本和跨模块回归固定到同一 Windows 候选，再由独立 Windows 环境只按 README 验证首次使用。真实服务接入另行验证。本标签提供编排工具源码，未包含独立验收的原生框架 CLI 候选包。

## Windows 稳定版验收条件

1. 列出支持的 Windows、Python 版本、可信插件以及随包提供的模型和 Harness 组合。实验适配器保持可选。
2. 从干净标签构建一个完整安装包，锁定依赖，不带本机路径、内部回执或凭据。用哈希锁定后续测试对象。
3. 在该包上跑通授权、检索、引用、执行、独立评审、授权写回；再撤权并模拟中断，验证重启后不重复派发或写入。
4. 对承诺支持的真实模型和 Harness，用公开样例和明确预算执行一次。由另一台干净 Windows 按公开文档验证首次安装、升级、备份恢复和回滚。
5. 全部必测项通过后，发布支持矩阵、已知问题、版本号和校验值。不同历史包的通过记录不能替代本次验收。
