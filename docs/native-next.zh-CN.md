# 从 Windows 编排工具到原生框架：下一批功能

核对基线：公开标签 v1.0.0-rc.1。下表以用户能运行的功能为边界；不同工作目录中已通过的专项测试不能拼成同一版本的验收。已知离线能力见[模块状态](framework-status.zh-CN.md)。

| 优先级及职责 | 已有什么 | 要交付什么；怎样才算完成 |
| --- | --- | --- |
| P0 双核心集成 | 原生知识 CLI 和 Agent/知识组合有独立离线构件，公开 ZIP 提供编排器 | 同一便携包用两个合成项目跑通授权检索、带来源的上下文、执行、独立评审和授权写回。仅有读授权时写入失败；撤权后旧引用读不到正文；中断恢复不多写一次。 |
| P1 Runtime、Registry、Skill | 父会话读取已审核子结果、技能固定版本已有专项 | 多宿主同时恢复时只允许一个继续；覆盖身份撤销、执行中升级和上下文超限。压缩只能处理允许省略的历史，必须保留策略、待处理工具调用、未解决错误和证据引用。 |
| P1 Core 与插件 | 可信插件的发现、替换、按项目停用已有离线样例 | 隔离不受信任插件并验证崩溃和越权拒绝不影响独立模块；首版未提供隔离前只承诺可信插件。 |
| P1 Workflow 与 Observability | 有限容量恢复、按项目查询和脱敏导出已分别验证 | 用既有 Scheduler 处理容量在等待中变化、重启后订阅续读；验证重复事件不会导致二次派发，跨项目观察不泄露内容。 |
| P1 Model 与 Harness | 离线模型替换、工具拒绝和部分 CLI 冒烟已有结果 | 按声明的每个客户端验证真实调用、故障和恢复。输出结果未知时不得自动切换后重发。每个 Harness 的调用和重试合计不超过 1 美元。 |
| P2 知识来源与领域扩展 | 合成数据验证了检索后端替换、跨项目读授权及引用 | 用公开样例测试一个真实来源：导入、更新版本、保持旧引用可追溯、撤销读取。再换连接器或技能包验证业务调用不变。LangGraph 实现继续暂停。 |

第一项的分工：集成侧固定同一构建和入口；知识侧提供读、写、撤权夹具；执行侧提供任务、评审及重启夹具。三者可并行准备，最终只能以同一个 ZIP 上的结果验收。

本分支先修补已有用户入口：首次运行示例；重开只读当前 Scheduler 台账，取得三项任务的有效验收和原登记时间。目录残缺、有效评审缺失时停止。运行时间仅用于辨认，不能作为验收凭据。
