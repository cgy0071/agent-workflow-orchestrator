# Agent Workflow Orchestrator (AWO)

[English](README.md) | 中文

AWO 让一个 AI 规划任务，另一个执行，再由独立审核者根据证据决定是否完成。你指定目标和权限，本地台账记录每一步。可以直接使用 AWO，也可选用 MAID 作为秘书。

## 怎么运作

![从请求到独立审核](docs/images/workflow-overview.zh-CN.svg)

任务只派发一次；后台监测交付，审核者决定接受、返修或拒绝。任务可以并行，有依赖的步骤等前置任务通过后再开始。

## 工作流内部

### 多角色派工与独立审核

告诉 Planner 目标、允许修改的范围以及怎样算通过。互不依赖的任务可以并行，需要前置结果的任务则等审核通过再开始。
Executor 提交文件和证据；Reviewer 独立检查，记录接受、返修或拒绝。

### 隔离工作区与本地合并队列

改代码时，可以给每项任务分配独立的 Git 工作区，避免多个执行者同时修改同一个检出目录。
通过审核的改动可以进入本地合并队列；如果目标分支已经变化或出现冲突，应查看合并结果，不能把「已验收」当作「已合并」。

## 哪些模块接在工作流上

![客户端、知识授权、状态面板和通知分别接在哪里](docs/images/integrations-overview.zh-CN.svg)

### 后台监控与状态面板

本地脚本监测交付和停滞，不需要反复调用模型重读对话。
打开默认只读的面板，就能看到哪些任务正在执行、等待审核或需要处理阻塞。

### 多客户端适配

Planner 和 Executor 可以分别使用受支持的客户端，不必为了协作换到同一工具。
按已安装的版本查看适配指南：能否派工、恢复会话或直连终端，取决于具体客户端。

### 项目知识库与带出处的检索

可以只读提取 Markdown 或文本型 PDF 的片段，再按主题搜索获准的文档和科研摘录；无需先知道文档编号，结果会标出原文位置或 PDF 页码。
中搜英时可用双语扩展，也可用项目术语表限定译法；系统先核对权限再排序，撤权后再次查询便不能读取该材料。

### 外部收件箱与通知

外部渠道可以把请求送入收件箱，由 Planner 查看。
反向的通知用于提醒：执行者需要授权或任务遇阻时提醒 Owner，证据就绪时提醒 Reviewer。

## 五条安全底线

1. 配置不等于授权：派工、发送通知和持续执行都需要明确许可。
2. 交付不等于验收，验收也不等于合并。
3. 每项任务只派发一次；发送结果不明时先核查，不盲目重发。
4. 只有当前控制者可以操作；执行者不能审核自己的工作。
5. 外部消息不能授权启动任务，也不能代答权限提示。
